# ConsoleReader — تدريب روبوت SPIKE Prime باليد أو من تطبيق ويب

برنامج **Pybricks** لروبوت **LEGO SPIKE Prime**: حرّك الروبوت بيدك على أرض الملعب وسجّل المسار قراءات الحساسات، فيطبع البرنامجُ برنامجَ سباق ذكيًا جاهزًا للنسخ والتشغيل — بنظام **Teach & Repeat**.

## الملفات

| الملف | الوصف |
|---|---|
| `as3.py` | النسخة الأصلية: التحكم من أزرار الـ Hub فقط |
| `as3_app.py` | نسخة التطبيق: نفس الوظائف + استقبال الأوامر من تطبيق الويب عبر البلوتوث (وأزرار الـ Hub ما زالت تعمل) + **استلام الكود من التطبيق وتنفيذه على الروبوت** مباشرة (`B` وحزم `N` ثم `E` ثم `G`). تطبع `# HUB_VERSION 6` عند البدء، وتحمل مكتبة برامج داخل الـ Hub (`W`/`V`/`J`/`D`) |
| `app/index.html` | تطبيق ويب (ملف واحد، بدون تثبيت) يعمل في Chrome على الكمبيوتر أو أندرويد ويتصل بالـ Hub عبر Web Bluetooth |
| `start_app.bat` | نقرة واحدة على ويندوز: يشغّل الخادم المحلي على المنفذ 8000 ويفتح `http://localhost:8000/app/` في Chrome تلقائيًا |
| `start_server.bat` | يشغّل الخادم فقط (بدون فتح Chrome على الكمبيوتر) ويعرض عناوين الجوال على الشبكة المحلية — للتحكم من الجوال |

## تشغيل سريع بنقرة واحدة (ويندوز)

انقر مرتين على **`start_app.bat`** (الموجود بجانب مجلد `app`)، أو على اختصار **ConsoleReader** على سطح المكتب:

1. يتحقق من وجود Python، ويعرض رسالة واضحة إن لم يكن مثبتًا.
2. يشغّل `python -m http.server 8000` من مجلد المشروع في **نافذة مصغّرة** بعنوان «ConsoleReader server».
3. ينتظر حتى يصبح المنفذ جاهزًا (حتى 15 ثانية)، ثم يفتح `http://localhost:8000/app/` في **Google Chrome** (وإن لم يجد Chrome يفتح المتصفح الافتراضي).
4. إذا كان الخادم يعمل بالفعل لا يشغّل نسخة ثانية — يفتح الصفحة فقط.

- **لإيقاف الخادم**: أغلق نافذة «ConsoleReader server» المصغّرة.
- الملف يتطلب وجوده بجانب مجلد `app` (يتحقق من ذلك ويعرض رسالة إن وُضع في مجلد آخر).
- يمكن سحب الملف إلى سطح المكتب مع اختيار «إنشاء اختصار» للوصول السريع.

## التشغيل على الجوال (أندرويد)

التطبيق صفحة ويب واحدة تتصل بالـ Hub عبر **Web Bluetooth** المدمج في متصفح الجوال. للتشغيل على الجوال:

1. **شغّل الخادم على الكمبيوتر** — انقر مرتين على **`start_server.bat`** (بجانب مجلد `app`): يشغّل الخادم فقط بدون فتح Chrome على الكمبيوتر، ويعرض في النافذة جاهزةً عناوين الجوال مثل `http://10.120.110.29:8000/app/`، مع تذكير بعلامة Chrome وبأمر جدار الحماية.
2. **اعرض عنوان الكمبيوتر على الشبكة** — افتح `cmd` واكتب `ipconfig`، وابحث عن `IPv4 Address` تحت `Wireless LAN adapter Wi-Fi` (مثل `10.120.110.29`).
3. **افتح الرابط في Chrome على الجوال**: `http://10.120.110.29:8000/app/` (استبدل العناوين بعنوانك).
4. **فعّل علامة السياق غير الآمن** — Web Bluetooth يتطلب `https` أو `localhost`، والرابط أعلاه `http://` فتحجبه Chrome. على الجوال افتح `chrome://flags/#unsafely-treat-insecure-origin-as-secure`، فعّلها، وأضف `http://10.120.110.29:8000` في الحقل الذي يظهر، ثم اضغط **Relaunch** وأعد فتح الرابط. الصفحة تكشف الحالة وتعرض هذه الخطوات تلقائيًا في صندوق تحذير أصفر إن فُتحت عبر `http://`.
5. اضغط «🔵 اتصال بالبلوتوث» واختر الـ Hub (البلوتوث يتصل من الجوال مباشرة — لا حاجة لبلوتوث الكمبيوتر).

**متطلبات**: أندرويد + Chrome (لا يدعمه آيفون/Safari أو Firefox)، والجوال والكمبيوتر على **نفس شبكة Wi‑Fi**.

**إن لم يصل الجوال إلى الخادم**: جدار حماية ويندوز يمنع المنفذ 8000 افتراضيًا. أضف القاعدة بتشغيل PowerShell **كنمدير**:

```powershell
New-NetFirewallRule -DisplayName "ConsoleReader web (TCP 8000)" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private
```

**بديل دائم بلا علامة**: قدّم الصفحة عبر `https` (مثلًا [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) أو GitHub Pages) فلا تحتاج إلى تفعيل العلامة — لكن للتدريب الميداني الـ LAN أسرع استجابة.

### الجوال وحده بلا كمبيوتر

يمكن تشغيل التطبيق **من الجوال نفسه** دون أي كمبيوتر، لأن الاتصال بالـ Hub يتم من البلوتوث المدمج في الجوال. الشرط الوحيد: الصفحة يجب أن تُقدَّم عبر `localhost` (وهو سياق آمن حتى مع `http://`، فلا حاجة لعلامة Chrome ولا لـ https):

1. ثبّت **[Termux](https://f-droid.org/packages/com.termux/)** من F‑Droid (نسخة Play Store قديمة).
2. `pkg install python`
3. انسخ **مجلد `app` كاملًا** (لا `index.html` وحده — فالصفحة تحتاج `sw.js` والأيقونات و`manifest.json`) إلى مجلد Termux، ثم `cd` إلى المجلد الأب.
4. `python -m http.server 8000`
5. افتح في Chrome على الجوال: `http://localhost:8000/app/` — يعمل البلوتوث مباشرة، ولا تحتاج إلى جدار حماية ولا إلى شبكة Wi‑Fi مشتركة.

> إن نسخت `index.html` وحده إلى مجلد ما، فالرابط الصحيح هو `http://localhost:8000/index.html` (بلا `/app/`)؛ وسيعمل البلوتوث لكن بلا تثبيت PWA ولا عمل دون إنترنت.

ينصّ تنبيه الصفحة نفسه على هذه الخطوات عند فتح الملف كـ `file://` (أي بعد نسخه مباشرة وفتحه بالنقرة — وهو ما **لا يعمل** لأن `file://` ليس سياقًا آمنًا).

## النشر على GitHub Pages (تطبيق PWA — الطريقة المفضّلة)

رفع الموقع على GitHub Pages يحوّله إلى **تطبيق ويب تقدّمي (PWA)**: يعمل برابط `https://` فيفتح **Web Bluetooth تلقائيًا** بلا علامة Chrome ولا Termux ولا جدار حماية ولا شبكة مشتركة، ويظهر بأيقونة على شاشة الجوال الرئيسية، ويعمل في الميدان **حتى بلا إنترنت** بعد أول تحميل.

### ما أُضيف للتطبيق

| الملف | الوصف |
|---|---|
| `app/manifest.json` | تعريف التطبيق: الاسم، الأيقونات، وضع «مستقل» (يظهر بلا شريط متصفح) |
| `app/sw.js` | Service Worker: يخزّن كل الأصول بعد أول تحميل ليعمل التطبيق دون إنترنت، ويحدّثها في الخلفية |
| `app/icon-192.png`<br>`app/icon-512.png`<br>`app/icon-maskable-512.png` | أيقونات التطبيق (192/512 بكسل + نسخة قابلة للقناع لأندرويد) |
| `index.html` (الجذر) | صفحة تحويل تفتح `app/` تلقائيًا — للوصول برابط المستودع مباشرة |

### خطوات النشر

1. أنشئ مستودعًا جديدًا على GitHub (عام أو خاص — **ملاحظة**: رفع الموقع على Pages يتطلب مستودعًا **عامًا** في الخطة المجانية).
2. ارفع الملفات (باستخدام Git أو تطبيق GitHub Desktop):
   ```bash
   git init
   git add .
   git commit -m "ConsoleReader PWA"
   git branch -M main
   git remote add origin https://github.com/<اسم المستخدم>/<اسم المستودع>.git
   git push -u origin main
   ```
3. في المستودع: **Settings ← Pages ← Source: Deploy from a branch ← Branch: main ← /(root) ← Save**.
4. انتظر دقيقة أو دقيقتين حتى يظهر الرابط: `https://<اسم المستخدم>.github.io/<اسم المستودع>/`

### تثبيته على الجوال كتطبيق

1. افتح الرابط في **Chrome على أندرويد**.
2. من قائمة Chrome (⋮) اختر **«تثبيت التطبيق»** أو **«إضافة إلى الشاشة الرئيسية»**.
3. يظهر التطبيق بأيقونته الخاصة وشاشة ملء الذاكرة (بلا شريط عنوان المتصفح).

بعد أول فتح، **يعمل التطبيق بلا إنترنت** تمامًا — التحكّم بالأسهم يذهب مباشرة من راديو البلوتوث في الجوال إلى الـ Hub، ولا يمرّ بالإنترنت إطلاقًا.

### ما لا يغيّره النشر

- **`as3_app.py` يجب أن يكون منزَّلًا على الـ Hub** عبر Pybricks Code على الكمبيوتر — رفع الموقع لا ينقله إلى الـ Hub.
- ملف برنامج السباق يُنزَّل من المتصفح كالمعتاد.
- عند تعديل الصفحة أو `sw.js`، ارفع التغييرات ثم أعد فتح الرابط. قد يتأخّر ظهور التحديث دقيقة أو دقيقتين، وقد تحتاج إلى سحب الصفحة للتحديث (pull-to-refresh) أو إغلاق التطبيق وإعادة فتحه.

### نقطة أمان

المستودع العام يعني أن **من يملك الرابط يستطيع فتح واجهة التحكّم**. لكنه لن يُوصل شيئًا ما لم يكن قريبًا من الـ Hub وفي وضع الاقتران. لزيادة الأمان استخدم مستودعًا خاصًا (يتطلب رفع Pages في خطة مدفوعة)، أو اجعل الرابط صعبًا لاكتشافه.

## التدريب من تطبيق الويب (بدل أزرار الروبوت)

1. افتح `as3_app.py` في **Pybricks Code** وشغّله/نزّله على الـ Hub مرة واحدة، ثم افصل Pybricks Code عن الـ Hub (البلوتوث يقبل اتصالًا واحدًا فقط).
2. افتح `app/index.html` في متصفح **Chrome** (كمبيوتر أو جوال أندرويد) عبر `https` أو `localhost` — مثلًا عبر GitHub Pages أو خادم محلي:
   ```bash
   python3 tools/dev_server.py          # يفتح /app/ تلقائيًا، ويُرسل no-store
   # ثم افتح http://localhost:8000/app/
   ```
   `tools/dev_server.py` مجرّد خادم تطوير: الجذر `/` يعيد التوجيه إلى `/app/`، ويمنع
   المتصفح من تخزين `index.html`/`sw.js` أثناء التعديل. للنشر العادي يكفي
   `python3 -m http.server 8000` من جذر المشروع.
3. اضغط «اتصال بالبلوتوث» واختر الـ Hub، ثم «▶ تشغيل برنامج التدريب» (أو شغّله من زر الـ Hub). انتظر ظهور `APP_READY` في سجل التطبيق وإضاءة الـ Hub باللون الأزرق.
4. ادفع الروبوت بيدك — أو حرّكه من أسهم التحكم عن بعد — إلى النقطة المطلوبة، ثم اضغط زر التطبيق المناسب:

| زر التطبيق | بديله على الروبوت | الوظيفة |
|---|---|---|
| تسجيل حركة `R` | RIGHT | تسجيل دوران ثم خط مستقيم |
| قراءة الحسّاس `L` | LEFT | قراءة عتبة الخط من الحسّاس الوحيد على C (للمعايرة) |
| نقطة خط ذكية `F` | CENTER+LEFT | بحث دقيق عن الخط `find_line` بالحسّاس الوحيد |
| متابعة خط `T` | CENTER+RIGHT | مقطع `follow_line` بالمسافة المجرَّبة |
| تراجع `U` | LEFT+RIGHT | حذف آخر تسجيل وإرجاع نقطة القياس |
| طباعة برنامج السباق `C` | CENTER | طباعة برنامج السباق الكامل في سجل التطبيق |

5. عند الانتهاء اضغط «🏁 طباعة برنامج السباق الكامل» — يُجهَّز البرنامج تلقائيًا في لوحة «📄 برنامج جاهز للتشغيل»، ثم اضغط **«📤 إرسال الكود وتشغيله على الروبوت»** فينفّذه الـ Hub فورًا بلا Pybricks Code وبلا ملفات. (ويمكن بدلًا من ذلك تنزيله كملف `race_program.py` وفتحه في Pybricks Code.)

يمكن الخلط بحرية بين أزرار التطبيق وأزرار الروبوت أثناء نفس جلسة التدريب، ويمكن استخدام مفاتيح لوحة المفاتيح `R L F T U C` وأسهم `↑↓←→` / `W A S D` على الكمبيوتر. الاختصارات تُقرأ بحسب **المفتاح الفيزيائي** (`e.code`) لا الحرف المكتوب، فتعمل كما هي مع تخطيط لوحة المفاتيح العربي أو الإنجليزي.

### التحكم عن بعد بالمحركات (بديل التحريك اليدوي)

لوحة أسهم في أسفل التطبيق تحرك الروبوت بالمحركات بدل دفعه باليد:

| زر التطبيق | مفتاح لوحة المفاتيح | الأمر | الحركة |
|---|---|---|---|
| ⬆️ للأمام | `ArrowUp` / `W` | `w` | دفع `RC_SPEED` مم/ث للأمام |
| ⬇️ للخلف | `ArrowDown` / `S` | `s` | دفع للخلف |
| ↺ لف يسارًا | `ArrowLeft` / `A` | `a` | دوران `RC_TURN` درجة/ث يسارًا |
| ↻ لف يمينًا | `ArrowRight` / `D` | `d` | دوران يمينًا |
| 🔼 محرك D + | `Q` | `u` | تحريك محرك المنفذ D بالاتجاه الموجب |
| 🔽 محرك D − | `E` | `j` | تحريك محرك المنفذ D بالاتجاه السالب |
| ⏹ إيقاف | `Space` | `x` | تباطؤ ناعم ثم تحرير المحركات (coast) |

- **اضغط مع الاستمرار**: الروبوت يتحرك ما دامت إصبعك على الزر، ويتوقف فور رفعه.
- **حركة ناعمة**: لا يقفز الروبوت من السكون إلى السرعة الكاملة. كل دورة (~30ms) يقترب من الهدف بمقدار محدود (`RC_ACCEL = 900` مم/ث² و`RC_TURN_ACCEL = 1200` درجة/ث²)، وعند الإفلات يتباطأ تدريجيًا ثم يحرّر المحركات — بلا انتفاضة ولا وقفة فجائية. خفّض القيم لجعل الحركة أنعم/أبطأ، وارفعها لاستجابة أسرع.
- **برنامج السباق أيضًا أنعم**: الأسطر الناتجة تحتوي `robot.settings(straight_acceleration=…, turn_acceleration=…)` (`MOVE_ACCEL` / `MOVE_TURN_ACCEL`).
- **أمان مبنيّ في البروتوكول**: التطبيق يعيد الأمر كل 250ms، والروبوت يتباطؤ ويتوقف تلقائيًا إذا توقّعت التكرارات (قطع الاتصال، خروج من الصفحة، نسيان الإصبع) — عدّل المهلة بـ `RC_FRAMES` في `as3_app.py`.
- **السرعة قابلة للتعديل**: `RC_SPEED = 120` مم/ث و`RC_TURN = 90` درجة/ث في أعلى قسم التحكم عن بعد في `as3_app.py`.
- **اتجاه الدوران**: في Pybricks القيمة الموجبة تعني **يمينًا** (مع عقارب الساعة) والسلبية **يسارًا**؛ لذلك `d` يرسل `+RC_TURN` و`a` يرسل `-RC_TURN`. إن ظهر الاتجاه معكوسًا على روبوتك (تركيب محرك بالعكس) اقلب الإشارتين في `handle_app_command` فقط.
- **تكامل مع التسجيل**: الحركة عن بعد تُحدّث عدّاد المسافة والجيروسكوب، فزر `R` (تسجيل حركة) يسجّلها تمامًا كحركة يدوية.
- أي أمر تدريب (`R/L/C/F/T/U/C`) أو أي زر على الـ Hub يوقف الدفع بنعومة (بانتظار السكون) قبل التنفيذ حتى لا تتداخل حركتان.
- يلزم إعادة نزّل `as3_app.py` على الـ Hub بعد هذا التحديث، لأن أحرف `w s a d x y z` جديدة ولا تفهمها النسخة القديمة.

### قراءة الحساسات تلقائيًا مع الحركة

بدل التوقف والضغط على «قراءة الحسّاس» (`L`) عند كل نقطة:

- **جمع صامت دائم**: الروبوت يقرأ **حسّاس الألوان الوحيد على المنفذ C** كل ~100ms ويجمع نطاق الانعكاس في الخلفية (أصغر/أكبر قيمة فقط — بلا قائمة عينات) لحساب عتبة الخط تلقائيًا.
- **بثّ أثناء الحركة فقط**: عندما يتحرك الروبوت (بالأسهم أو باليد — يُكتشف من تغيّر عدّاد المسافة/الجيروسكوب) يطبع سطرًا مضغوطًا في السجل:

  ```
  # T d=190 h=9 C=11
  ```

  `d` = المسافة (مم) • `h` = الاتجاه (درجة) • `C` = انعكاس الحسّاس الوحيد على المنفذ C. لا يطبع شيئًا عند السكون حتى لا يمتلئ السجل.
- **مفتاح في التطبيق**: «📡 قراءة الحسّاس تلقائيًا مع الحركة» (مُفعّل افتراضيًا) — يرسل `y` للتشغيل و`z` للإيقاف، ويمكن إرسال الحرفين يدويًا.
- العينات المجمّعة تُحسّن `LINE_THRESHOLD` في برنامج السباق الناتج تلقائيًا، وتظهر خلاصتها في سطر «عتاة الخط المقترحة» أسفل البرنامج.

### 💻 استوديو البرمجة (محرّر + مكتبة + برامج على الـ Hub)

لوحة مستقلة في التطبيق تجمع كل ما يخصّ برمجة الروبوت في مكان واحد:

- **📝 محرّر Python** بأرقام أسطر، و`Tab` يُدخل مسافتين، وتحويل مباشر للبرنامج المولَّد من التدريب بزر «⤵️ من البرنامج المولَّد».
- **🔍 فحص قبل الإرسال** (`checkProgram`): يتحقّق من توازن الأقواس والاقتباسات (مع رقم السطر)، ومن وجود أوامر قابلة للإرسال، ومن تجاوز حدّ الـ Hub (90 أمرًا)، ويذكر `LINE_THRESHOLD` إن وُجد أو ينبّه لغيابه. **لا يُعلن نجاحًا كاذبًا**: زر الإرسال يرفض المتابعة عند أي خطأ، والتأكيد النهائي يبقى من الـ Hub نفسه.
- **📚 مكتبة برامج في المتصفح** (`localStorage`، حتى 40 برنامجًا): حفظ باسم (الاسم نفسه = تحديث)، فتح في المحرّر، تشغيل مباشر، تنزيل `.py`، وتصدير/استيراد المكتبة كاملة (`console_reader_library.json`).
- **🤖 برامج على الـ Hub نفسه** (حتى 4، في RAM): «💾 حفظ» يخزّن البرنامج الذي أرسلته آخر مرة باسم، و«▶ تشغيل» يرسله `J <رقم>` فيعمل الروبوت **بلا هاتف**، و«🗑» يحذفه بـ `D <رقم>`، و«🔄 تحديث» يقرأ القائمة بـ `V`.

**حدّ مهم يجب معرفته:** ما ينفّذه الـ Hub لحظيًا هو **أوامر الحركة** فقط
(`robot.turn` · `robot.straight` · `find_line` · `align_on_line` · `follow_line`).
الحلقات والشروط والمتغيّرات وحساب العتبة لا تُرسَل — لأن Pybricks لا يوفّر واجهة تنفيذ كود
عشوائي عبر البلوتوث. لذلك يبقى الملف الكامل للتنزيل وفتحه في **Pybricks Code**،
والتطبيق يقول لك بالضبط كم أمرًا سيُرسل وكم سطرًا لن يُرسل قبل أن ترسل شيئًا.
اسم البرنامج على الـ Hub محدود بـ **20 حرفًا**، والبرامج المحفوظة هناك **تُفقد بإعادة تشغيل الـ Hub** (النسخة الدائمة هي مكتبة المتصفح).

### 📤 إرسال الكود إلى الروبوت وتنفيذه مباشرة

بدل تنزيل ملف `.py` وفتحه في Pybricks Code، يستطيع التطبيق أن **يبثّ أوامر البرنامج نفسه** إلى الـ Hub
عبر البلوتوث، فيحفظها الروبوت وينفّذها خطوة بخطوة:

| الزر | الأمر المُرسل | ما يحدث |
|---|---|---|
| 📤 إرسال الكود وتشغيله على الروبوت | `B` + حزم `N` + `E` + `H` + `G` | يبثّ التطبيق أوامر البرنامج، **ينتظر تأكيد الـ Hub** بعدد الأوامر، ثم يبدأ التنفيذ |
| 📥 إرسال فقط | `B` + حزم `N` + `E` | يحفظ الـ Hub الكود بلا تنفيذ (نفّذه لاحقًا بالزر الأول) |
| ⏹ إيقاف التنفيذ | `x` | يكبح الروبوت فورًا (`brake`) أثناء المسار |

**سرعة الإرسال:** كان التطبيق يرسل حرفًا لكل كتابة GATT (‏~900 كتابة لبرنامج من 100 أمر ≈
15–25 ثانية). الآن يرسل **حزمًا** من 90 بايت: `N` + بايتان طول (little‑endian) + الحمولة،
أي 15–30 كتابة فقط. والـ Hub يجمّع الحزم بنفسه (الأسطر قد تنقسم بين حزمتين، وهذا مقصود
ومُختبر). الوضع القديم `K … E` ما زال مدعومًا للتوافق.

**تأكيد قبل النجاح:** التطبيق لا يقول «أُرسل» إلا بعد أن يطبع الـ Hub
`# ✓ استُلم الكود: N أمرًا` ويطابق العدد المُرسل. إن اختلف العدد أو لم يصل التأكيد ظهر
تنبيه أحمر بدل رسالة نجاح كاذبة.

- **الكود نفسه هو المُرسَل**: التطبيق يحوّل سطور دالة `run()` — أو أي أسطر `robot.turn` / `robot.straight` / `find_line` / `align_on_line` / `follow_line` — إلى أوامر قصيرة:
  `T 30` = `robot.turn(30)` • `S 500` = `robot.straight(500)` • `F 1 250` = `find_line(1, 250)` • `A 25` = `align_on_line(25)` • `L 400 L` = `follow_line(400, "L")` • `L -250 R` = متابعة الخط أثناء **الرجوع** للخلف.
- **قابل للتعديل قبل الإرسال**: لوحة «📄 برنامج جاهز للتشغيل» صارت قابلة للكتابة — غيّر زاوية أو مسافة أو احذف سطرًا ثم أرسله، والروبوت ينفّذ ما تراه على الشاشة (التعليقات والسطور غير المدعومة مثل `robot.reset()` تُتجاهل تلقائيًا ويُخبرك التطبيق بعددها).
- **تنفيذ غير حاجز**: الروبوت لا يستخدم `robot.straight()`/`robot.turn()` الحاجزة، بل يتقدّم دفعة صغيرة كل دورة (~30ms) نحو الهدف بمقارنة عدّاد المسافة واتجاه الجيروسكوب، فيبقى يستقبل `x` ويستجيب لأي زر على الـ Hub في أي لحظة.
- **الإيقاف يكبح فعليًا**: الإلغاء أو نهاية المسار يستخدم `robot.brake()` لا `robot.stop()` (الأخير = coast، أي أن الروبوت قد يتابع مسافة محسوسة بعد إيقاف الطوارئ). `stop()` بقي فقط لتحرير المحركات عند التحكم اليدوي عن بعد.
- **حدود الأمان**: أقصى عدد أوامر `RUN_MAX_LINES = 90`، وأقصى طول سطر `RUN_MAX_LINE_LEN = 24` (السطر الأطول يُتجاهل كاملًا — لا يُقتطع، لأن اقتطاع `S 4000` يعطي `S 400`)، وأقصى مدة تنفيذ `RUN_MAX_MS = 120000` (دقيقتان). سماحية الوصول `RUN_TOL_DIST = 4` مم و`RUN_TOL_ANG = 2` درجة.
- **مهل الاستلام**: إن انقطع الإرسال بعد `B`/`K` بلا `E`، يخرج الـ Hub من وضع الاستلام تلقائيًا بعد `CODE_TIMEOUT_MS = 5000` ويحتفظ بالكود السابق — بدل أن يبتلع كل الأوامر (بما فيها `x`) بلا نهاية.
- **نبضة حياة أثناء التنفيذ**: التطبيق يرسل `p` كل ثانية؛ فإن توقفت 2.5 ثانية (`HEARTBEAT_MS`) — انقطاع بلوتوث، إغلاق التبويب، تعليق الجهاز — يكبح الـ Hub الروبوت ويُلغي التنفيذ. `q` تُلغي المراقبة.
- **عتاة الخط من اللوحة**: التطبيق يرسل `H <رقم>` (‏`H 49`) من قيمة `LINE_THRESHOLD` المكتوبة في اللوحة، فينفّذ الـ Hub بنفس العتبة المعروضة. أما سرعات `RUN_*` و`FOLLOW_GAIN` فتبقى في `as3_app.py` — **لا** تُرسل مع الكود.
- **سرعات التنفيذ** قابلة للتعديل أعلى قسم التنفيذ في `as3_app.py`: `RUN_SPEED = 220` مم/ث، `RUN_TURN_RATE = 130` درجة/ث، `RUN_SEARCH_SPEED = 80`، `RUN_FOLLOW_SPEED = 90`.
- **تقدّم التنفيذ** يظهر في السجل سطرًا لكل مقطع (`# 2/5  robot.straight(300)`) مع بداية ونهاية واضحتين، ويُصمت بثّ سطور `# T` أثناء التنفيذ لئلا يمتلئ السجل.
- **بعد الانتهاء أو الإلغاء** تُعاد نقطة القياس إلى موضع الروبوت الحالي، فلا يُسجَّل مسار التنفيذ كأنه حركة يدوية عند الضغط على `R` لاحقًا.
- **يلزم تحديث `as3_app.py` على الـ Hub** لهذه الميزة؛ النسخة القديمة تتجاهل `K/E/G` فلا يحدث شيء، وبقية الوظائف تبقى كما هي.
- **لماذا لا يُرفع الملف نفسه؟** بروتوكول Pybricks المتاح لـ Web Bluetooth لا يدعم كتابة الكود المصدري أو الـ bytecode إلى الـ Hub (Pybricks Code يفعل ذلك ببروتوكول أعمق غير متاح للمتصفح)، لذلك يرسل التطبيق **أوامر المسار** ويشغّلها الـ Hub ببرنامجه الموجود عليه — نفس النتيجة عمليًا وبلا ملفات.

### تصدير البرنامج والبيانات (نسخ/تنزيل بضغطة)

عند الضغط على «🏁 طباعة برنامج السباق الكامل» يرسل الروبوت البرنامج محاطًا بعلامتين خفيتين
(`#@@PROGRAM_BEGIN@@` / `#@@PROGRAM_END@@`) لا تظهران في السجل. التطبيق يلتقط ما بينهما ويعرضه
في لوحة **«📄 برنامج جاهز للتشغيل على الروبوت»**:

| الزر | الناتج |
|---|---|
| 📋 نسخ البرنامج | ينسخ ملف Python كاملًا إلى الحافظة (مع بديل تلقائي إن منع المتصفح الحافظة) |
| ⬇️ تنزيل race_program.py | يحفظ ملفًا جاهزًا: افتحه في **Pybricks Code** → «Download and Run» |
| 📋 نسخ السجل كاملًا | نسخ كل مخرجات الروبوت |
| ⬇️ تنزيل السجل (.txt) | ملف نصي بكل السجل |
| ⬇️ تنزيل القياسات (.csv) | يحوّل سطور `# T` إلى جدول CSV (`t_s,d_mm,h_deg,C_reflect`) للتحليل في Excel |

- الملف الناتج **كامل وصالح لغويًا** (`import` + تهيئة المحركات والحساسات + `robot.settings` للنعومة + الدوال الذكية عند الحاجة + `def run()` + استدعاء `run()`) — لا يحتاج أي تعديل.
- الزمن في CSV تقديري (0.1 ثانية لكل عينة، وهو معدّل البثّ الفعلي).
- العلامتان تحتاجان تشغيل نسخة `as3_app.py` المحدَّثة؛ مع النسخ الأقدم **تمتلئ اللوحة تلقائيًا** بالاستخراج من السجل (بين «برنامج السباق الذكي» و«نهاية المسار») ويظهر تنبيه أصفر بذلك، كما يبيّن سطر **«علامات البرنامج»** في صندوق التشخيص هل نسخة الـ Hub محدَّثة. تُعاد الملء عند كل طباعة جديدة، وزر «تفريغ» يمنع الملء التلقائي حتى يُطبع برنامج جديد.
- **التشغيل المباشر** صار متاحًا بزر «📤 إرسال الكود وتشغيله»: يبثّ التطبيق أوامر المسار إلى الـ Hub فينفّذها بلا Pybricks Code (انظر القسم أعلاه). ويبقى التنزيل كملف `race_program.py` متاحًا لمن يريد نسخة مستقلة أو تعديلها في Pybricks Code.

### كيف يعمل الاتصال؟

- الروبوت (`as3_app.py`) يستطلع `usys.stdin` دون حظر عبر `uselect.poll`، وكل حرف يصله يُوجَّه: `R/L/C/F/T/U` إلى دالة زر الـ Hub المقابلة، و`w/s/a/d/x` إلى وحدة التحكم عن بعد، و`y/z` إلى تشغيل/إيقاف القراءة التلقائية، و`B … N/E` (أو `K … E`) لاستلام الكود، و`H` لعتبة الخط، و`p/q` لنبضة الحياة، ثم `G` للتنفيذ (`x` يوقف التنفيذ الجاري).
  - **فحص الاستجابة (v6):** `?` يطبع `# ✓ HUB_ALIVE v6 <عدد أوامر الجاهزية> <ذاكرة حرة>` — يستخدمه التطبيق ليعرف أن برنامج التدريب يعمل فعلًا قبل أن يعتمد على الأوامر. شارة «الـ Hub: يستجيب ✓ / لا يستجيب ✗» في شريط الحالة (اضغطها لفحص يدوي)، وفحص تلقائي بعد الاتصال وبعد «▶ تشغيل برنامج التدريب».
  - **مكتبة الـ Hub (v6):** `W <اسم>\n` يحفظ البرنامج المستلم، `V` يطبع `# V <عدد>` ثم `# P <رقم> <عدد الأوامر> <الاسم>` لكل برنامج ثم `# V end`، `J <رقم>\n` يشغّل برنامجًا محفوظًا، `D <رقم>\n` يحذفه (حتى `MAX_PROGRAMS = 4`).
- التطبيق يتصل بخدمة Pybricks BLE الرسمية (`c5f50001-…`) ويرسل الأوامر كـ **WRITE_STDIN** (الأمر `0x06`)، ويستقبل مخرجات `print()` من الروبوت كأحداث **WRITE_STDOUT** فيعرضها في السجل — وهي نفس آلية Pybricks Code، وتتطلب Pybricks firmware ‏`>= 3.3`.
- يوجد وضع بديل تلقائي عبر Nordic UART Service للبرامج الثابتة الأقدم.
- **إن ظهرت رسالة «لم أجد أوامر قابلة للإرسال»**: التطبيق صار يشرح السبب بنفسه. الأسباب التي عولجت: الأرقام العربية/الفارسية (`robot.turn(٩٠)` تُحوَّل تلقائيًا إلى `90`)، و`run()` الذي فقد مسافاته البادئة عند النسخ واللصق (خطة بديلة تقرأ الأوامر)، وأمران في سطر واحد (`robot.turn(90); robot.straight(200)`)، والأوامر المكتوبة داخل دالة غير `run()` أو داخل جسم دالة مساعدة. ويبقى الحدّ: المسموح فقط `robot.turn` / `robot.straight` / `find_line` / `align_on_line` / `follow_line`.
- **إن ظهرت رسالة «لم يصل تأكيد الـ Hub»**: التطبيق ينتظر سطر `# ✓ استُلم الكود: N` من الـ Hub. الأسباب الشائعة، بترتيب الاحتمال: (1) النسخة التي تعمل على الـ Hub قديمة ولا تعرف الحزم `B/N` — أعد تنزيل `as3_app.py` v6؛ (2) برنامج التدريب لا يعمل أصلًا — اضغط «▶ تشغيل برنامج التدريب» ثم تأكّد من شارة «الـ Hub: يستجيب ✓»؛ (3) البرنامج أكبر من حدّ الـ Hub (90 أمرًا) فرفض بعضه. صار التطبيق يميّز هذه الحالات بنفسه: يفحص الاستجابة بـ `?` ثم يقول «الـ Hub لا يستجيب» أو «يعمل لكنه رفض/لم يؤكّد» مع آخر سطر قاله الـ Hub.
- لا يعمل Web Bluetooth على آيفون/Safari أو Firefox.

## التصحيح الذكي في برنامج السباق الناتج

- **`find_line`** — يتقدّم ببطء حتى يكشف الحسّاس الوحيد (C) خطًا فيتوقّف (أدق من المسافة المفتوحة).
- **`align_on_line`** — يدور حول نفسه في اتجاه واحد حتى يرى الحسّاس الخط فيتوقّف (بحث بالدوران). نقطة الخط الذكية `F` صارت `find_line` وحدها: المحاذاة لم تعد ذات معنى مع حسّاس واحد.
- **`follow_line`** — يتبع إحدى حافتي الخط بالحسّاس نفسه بتحكّم تناسبي P؛ الثابت `FOLLOW_SIDE = "L"` في أعلى الملف يحدّد الحافة (اقلبها إلى `"R"` إن ابتعد الروبوت عن الخط على ملعبك).
- **عتبة الخط** تُحسب تلقائيًا من نطاق الانعكاس الذي تُجمعه أثناء **الحركة فقط** (منتصف المسافة بين أفتح وأظلم قياس، بشرط أن يكون الفرق ≥ 25)، وإلا تُستخدم `30`. كانت العينات تُجمع حتى عند السكون، فكانت عيّنة واحدة تحت ظلّ اليد أو روبوت مرفوع تُفسد العتبة.
- **`follow_line` بالمسافة السالبة** تتبع الخط أثناء الرجوع للخلف (كان `abs(diff_dist)` يلغي الاتجاه).

## ذاكرة الهاب وخطأ `MemoryError`

برنامج التدريب يعمل على الـ Hub نفسه، وذاكرته محدودة جدًا بعد تحميل Pybricks (بضعة عشر كيلوبايت قابلة للاستخدام). كان الناتج الآلي يُبنى من قالب نصي واحد كبير (~1.5KB) مع ثلاث استدعاءات `str.replace()`، وكل استدعاء يخصّص نسخة كاملة جديدة من القالب، وقد يفشل الطلب:

```text
MemoryError: memory allocation failed, allocating 1569 bytes
```

عندها كان ينتهي البرنامج كله (Traceback يوقف الحلقة). ما نُفّذ الآن:

- تُبنى أسطر الدوال المساعدة (`find_line` / `align_on_line` / `follow_line`) كقائمة نصوص قصيرة، بلا قالب كبير وبلا `replace` — المخرجات **مطابقة تمامًا** للنسخة القديمة (تم التحقق بمقارنة سطرًا بسطر)، ولا يُطلب أي كتلة كبيرة مرة أخرى.
- **عيّنات الانعكاس لم تعد قائمة**: كان يُحفظ حتى 400 عدد (`~3.2KB` + `pop(0)` في كل قراءة) لحساب عتبة لا تحتاج إلا أصغر قيمة وأكبرها. الآن عدّادان في كائن `SampleRange` (`refl`): ذاكرة ثابتة، بلا تخصيص في المسار الساخن.
- **سقوف صريحة**: `MAX_ACTIONS = 60` تسجيلًا، `RUN_MAX_LINES = 90` أمرًا، وحذف العينات الساكنة من حساب العتبة. عند بلوغ أي سقف تُطبع رسالة واضحة بدل `MemoryError`.
- **قياس فعلي عند البدء**: يطبع الـ Hub `# ذاكرة حرة: <N> بايت` و`# HUB_VERSION 6` وعدد البرامج المحفوظة، فيمكنك معرفة الهامش المتاح على روبوتك بدل التخمين.
- **مكتبة الـ Hub بلا نسخ نصوص**: البرامج المحفوظة تشير إلى **نفس قوائم المقاطع** التي ينفّذها `G` (لا نصوص أوامر مكرّرة)، فالحدّ 4 برامج مقيّد بالذاكرة الحرة المقاسة لا بتخمين.
- `do_print_program` تلتقط `MemoryError`، وتغلق علامات الالتقاط `#@@PROGRAM_END@@`، وتطبع رسالة عربية واضحة بدل انتهاء البرنامج.
- لو فشل أمر آخر بسبب الذاكرة، تُطبع رسالة تحذير وتستمر الحلقة (الروبوت لا يتوقف).
- التطبيق يرفض عرض أي برنامج لم يصل حتى سطر `# --- نهاية المسار ---`، ويعرض شارة «⚠ فشلت الطباعة (نفدت الذاكرة)» بدل نص ناقص يبدو سليمًا.

نصيحة: إذا تكرر النفاد رغم ذلك، احذف بعض التسجيلات (`U` / `LEFT+RIGHT`) ثم أعد الطباعة.

```bash
python -m unittest discover -s tests -t tests -v   # 41 اختبارًا لمنطق الـ Hub
node --test tests/web.test.mjs                     # 17 اختبارًا لمنطق التطبيق
python tools/check_sync.py                         # تزامن as3.py مع as3_app.py
node --check app/sw.js && python -m py_compile as3.py as3_app.py

# اختياري: اختبار الواجهة نفسها في DOM محاكى (محرّر/مكتبة/فحص)
npm install jsdom && node tests/ui_smoke.mjs
```

- `tests/stubs/` وحدات Pybricks وهمية (Hub، محركات، حساسات، `stdin`، `StopWatch` بساعة
  يتحكم بها الاختبار)، و`tests/hub_loader.py` ينفّذ الملف حتى «البرنامج الرئيسي» فقط
  (لأن الحلقة `while True` لا تنتهي) — فنختبر التوليد واستلام الكود والتنفيذ بلا هاردوير.
- تغطية الاختبارات: ترجمة برنامج السباق الناتج من الملفين، حدود العتبة، استلام الحزم
  (‏`B/N/E`) بكل أحجام التقسيم، السطر الطويل، `E` بلا سطر جديد، مهلة الاستلام، تأكيد العدد،
  `H` قبل `G`، الكبح عند الإلغاء، نبضة الحياة، ومكتبة الـ Hub (`W`/`V`/`J`/`D` وحدّها).
- اختبارات JS تغطي تحويل البرنامج إلى أوامر، بناء الحزم، فحص الكود (`checkProgram`)،
  ودوال المكتبة (`libNormalize` / `libUpsert` / `libRemove` / `parseHubList`).
- `tests/ui_smoke.mjs` يفتح `app/index.html` في jsdom ويتأكد من المحرّر وأرقام الأسطر
  وتقرير الفحص وحفظ/تحميل/حذف المكتبة — ويتخطّى نفسه إن لم يكن jsdom مثبَّتًا.
- `tools/check_sync.py` يفشل إن اختلفت أي دالة مشتركة بين `as3.py` و`as3_app.py`
  (‏`setup_lines` / `smart_helpers_lines` / `format_seg` / `estimated_threshold` …)،
  لأن هذا الاختلاف حدث فعلًا سابقًا (‏`robot.settings` أُضيف لنسخة واحدة).
- `.github/workflows/tests.yml` يشغّل كل ذلك في CI تلقائيًا.

## ملاحظات

- البرنامج لا يحفظ ملفًا على الروبوت؛ برنامج السباق يُطبع في السجل، ويجهّزه التطبيق للنسخ أو التنزيل كملف `.py`، ويمكن إرسال أوامره إلى الـ Hub وتنفيذها مباشرة من التطبيق (انظر «📤 إرسال الكود إلى الروبوت»).
- الحركة تُسجَّل «دوران ثم مستقيم» فقط؛ لا تُسجَّل المنحنيات اليدوية كمنحنى واحد.
- الحركات الأصغر من 5 مم أو درجتين تُتجاهل (ضجيج اهتزاز اليد).
- **تحديث الصفحة المثبَّتة**: كان الـ Service Worker يقدّم نسخة الصفحة القديمة إلى الأبد
  (كان يخدم طلبات التنقّل من `./index.html` بينما يكتب التحديث تحت `/app/`). أُصلح ذلك
  ورُفع اسم الذاكرة إلى `consolereader-v4`؛ عند تعديل الصفحة أو `sw.js` **ارفع اسم الذاكرة**
  أيضًا، وإلا تأخّر وصول التحديث للأجهزة المثبَّتة.
- **السجل محدود** بـ 3000 سطر (بعدها تُقصّ أقدم الأسطر ويظهر تنبيه بذلك) حتى لا تتجمّد
  الواجهة في الجلسات الطويلة؛ وملف CSV للقياسات يستخدم **طوابع زمنية حقيقية** الآن.
- **الشاشة لا تنام** أثناء الاتصال (`Wake Lock`) لأن نومها يوقف النبضات، ويظهر زر
  «🔁 إعادة الاتصال» عند انقطاع البلوتوث، مع إمكانية تشغيل أزرار التحكم بمفتاح `Enter`.
- **نقطة أمان للشبكة المحلية**: `start_server.bat` يخدم مجلد المشروع كله على شبكة Wi‑Fi
  (بما فيه ملفات Python) لأن المسار `/app/` هو المسار الموثَّق. لو أردت تقليل السطح،
  استخدم `python -m http.server 8000 --directory app` وافتح `http://<ip>:8000/`،
  أو أضف قاعدة جدار حماية تقصر المنفذ 8000 على أجهزتك.
